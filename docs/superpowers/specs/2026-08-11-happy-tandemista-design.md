# happy_tandemista — дизайн и план реализации

## Контекст

Продукт для дропзоны: автоматический сбор видео тандем-прыжка с носителей, метчинг с клиентом, анализ, автоматический монтаж и доставка готового ролика (по образцу FreeFallFilms, Shred Video, Team Cutaway). Сейчас этот процесс на дропзонах ручной: оператор перекидывает файлы с карт, ищет чьи они, монтирует в редакторе — часы работы на каждый прыжковый день.

Стратегия: сначала пилот на одной дропзоне, затем SaaS для многих. Поэтому проектируем single-tenant-развёртывание, но с `dropzone_id` у всех сущностей и без решений, блокирующих мульти-тенантность.

Проект стартует с нуля в пустой папке `/Users/komo4ekk/happy_tandemista`.

## Принятые решения (согласованы с пользователем)

- **Пользователь**: сначала своя дропзона, потом SaaS.
- **Сбор**: оба пути — станции с картридером (аплоадер на любом числе компьютеров ДЗ) и Wi-Fi-автовыгрузка с камер.
- **Метчинг**: авто-предложение (время + манифест + владелец камеры) + подтверждение оператора одним кликом.
- **Источники ролика**: всегда интервью на земле + прыжок + съёмка приземления; handcam и внешний оператор в разных комбинациях.
- **Монтаж**: авточерновик + ревью оператора перед публикацией.
- **Вычисления**: всё в облаке.
- **Доставка**: купившим пакет — сразу всё; остальным — превью с вотермарком + оплата постфактум.
- **Манифест**: свой мини-манифест в продукте; интеграции с внешними системами (Burble и т.п.) — позже.
- **MVP-фокус**: ядро автомонтажа (файлы → черновик → ревью → рендер) при ручной загрузке; остальное следом.
- **Определение фаз**: телеметрия + звук КАК ОСНОВА, но CV обязателен и равноправен — должен находить фазы (отделение, раскрытие) и лучшие моменты (эмоции) даже когда метаданных нет.
- **Стек**: Python (FastAPI) + ffmpeg + PostgreSQL + S3-совместимое хранилище + Celery/Redis + Next.js. Аплоадер — кросс-платформенный десктоп (Windows + macOS из одной кодовой базы, рекомендация Tauri).
- **Хранилища**: аплоадер складывает материал в настроенные хранилища ДЗ (Яндекс.Диск и/или сетевой диск и/или S3) через абстракцию StorageBackend; пайплайн забирает оттуда же.
- **Варианты монтажа** на прыжок: полный (16:9, ~2–4 мин), эмоции (16:9 и 9:16, ~60–90 с), хайлайты (9:16, 15 с, для сториз; 16:9-вариант — опционально как ещё один шаблон).
- **Оплата**: абстракция PaymentProvider; адаптеры ЮKassa (РФ, 54-ФЗ) и Stripe (США/мир); мультивалютность (валюта — настройка ДЗ); PayPal — бэклог.
- **Бэклог** (не MVP, но не блокировать архитектурно): личный кабинет ДЗ с кастомизацией шаблонов/брендинга и инструментами допродаж; редактор шаблонов; интеграции с внешними манифест-системами; зависимость набора вариантов монтажа от купленного пакета.

## Архитектура

```
Аплоадер (Tauri, Win/macOS, N компьютеров ДЗ)      Wi-Fi выгрузка с камер
        │  копирует в хранилище ДЗ + регистрирует в API      │
        ▼                                                    ▼
   StorageBackend (Я.Диск / S3 / сетевой диск, мультилокация файлов)
        ▼
   Облако: FastAPI ── PostgreSQL ── Celery/Redis
        ▼
   Воркеры (Python + ffmpeg + CV):
   телеметрия → аудио-профиль → CV-разметка → таймлайн → EDL×варианты → прокси → финальный рендер
        ▼
   Next.js: админка оператора (манифест, метчинг, ревью) + клиентская страница (просмотр/оплата)
```

### Компоненты

- **API-сервер** (FastAPI): манифест, регистрация файлов, статусы, публикация, клиентские страницы, вебхуки оплат.
- **Хранилище**: абстракция `StorageBackend` с реализациями `s3` (AWS/Яндекс Object Storage/MinIO), `yandex_disk` (REST API), `network_drive` (SMB/локальная папка). У ДЗ настроено 1+ хранилищ; `MediaFile` хранит список локаций. Прокси и рендеры кладутся туда же.
- **Очередь** (Celery + Redis): конвейер `извлечь телеметрию → прокси → анализ фаз → CV-разметка → таймлайн → черновики → рендер`; каждый шаг — отдельная ретраящаяся задача.
- **Воркеры**: ffmpeg-рендер, парсинг GPMF, аудио-анализ, вызовы CV-модели.
- **Аплоадер** (Tauri + React, Windows `.msi` / macOS `.dmg`, автообновление): детект карты (WM_DEVICECHANGE / DiskArbitration), определение Device по fingerprints, дедупликация по хэшу, копирование в хранилища ДЗ, регистрация в API, докачка после обрывов, прогресс «можно вынимать карту». Wi-Fi-выгрузка камер приземляется в отслеживаемую папку и подхватывается тем же механизмом.
- **Веб** (Next.js, один фронт с ролями): админка (взлёты/клиенты/устройства, очередь метчинга, ревью катов с плеером и таймлайном фаз, правка границ/кропа, публикация) + клиентская страница по ссылке-токену (все опубликованные варианты; для неоплативших — превью с вотермарком + покупка).

### Модель данных (ключевое)

- **Dropzone** — тенант; настройки: валюта, payment_provider, хранилища, набор вариантов монтажа.
- **User** — роли: админ ДЗ, манифест, инструктор, внешний оператор, ревьюер.
- **Load** (взлёт), **Customer**, **TandemJump** (клиент + инструктор + опц. внешний оператор + взлёт + видеопакет).
- **Device**: `name`, `kind` (gopro/insta360/dslr/phone/other → какой парсер телеметрии), `role` (handcam/outside/ground_interview/ground_landing/mixed → в какие слоты шаблона попадают кадры), `owner_user_id` (nullable — стойка интервью принадлежит ДЗ), `clock_offset_seconds` (авто-калибровка по ручным исправлениям метча и аудио-кросс-корреляции), `fingerprints` (серийник из MP4, volume ID карты, паттерн имён, MAC — для автоопределения устройства аплоадером; незнакомая карта → один раз спросить «чья камера»), `upload_source_id`, `active`.
- **UploadSource**: `kind` = uploader_agent / cloud_folder / camera_wifi / manual_web; `config` (JSON: OAuth-токены, пути). Файл хранит источник — доп. сигнал метчинга.
- **MediaFile**: локации в хранилищах, источник/устройство, времена начала-конца, хэш, статус, телеметрия.
- **JumpCut** — один на вариант монтажа (`full_16x9`, `emotions_16x9`, `emotions_9x16`, `highlights_9x16`): EDL, статус (черновик → ревью → опубликован), ссылки на прокси/рендер. Анализ общий на прыжок, варианты — шаблоны поверх одного таймлайна.
- **Order** — заказ постфактум: сумма, валюта, провайдер, статус.

### Метчинг (авто + подтверждение)

1. Файл → метаданные: устройство → владелец → тип источника; время съёмки из контейнера/телеметрии + `clock_offset`.
2. Пересечение по времени с окнами прыжков (интервью ~30 мин до взлёта, приземление ~20 мин после).
3. Сужение по людям: handcam инструктора X — только к прыжкам X; файлы оператора Y — к прыжкам с Y.
4. Высокая уверенность → автометч; низкая → очередь «требует подтверждения» с превью-кадрами. Немэтченные файлы никогда не пропадают (очередь «неразобранное»).
5. Исправления оператора логируются → калибровка `clock_offset`.

### Движок анализа и автомонтажа

1. **Сигналы по файлу**: GPMF-телеметрия (GoPro: высота, верт. скорость, ускорение, GPS; Insta360 — гироскоп через SDK; прочие — пропуск), аудио-профиль (огибающая+спектр: рёв ветра/тишина купола/речь), CV-разметка мультимодальной моделью по кадрам ~1 fps (фазы без телеметрии; эмоции, улыбки, взгляд в камеру, качество кадра; координаты лиц для автокропа 9:16). CV — обязательный компонент: фазы и лучшие моменты должны находиться даже при полном отсутствии метаданных.
2. **Таймлайн прыжка**: сведение сигналов всех файлов; синхронизация камер по аудио-кросс-корреляции + clock_offset; фазы `interview → boarding → climb → exit → freefall → deployment → canopy → landing → after` с границами и уверенностью. При наличии обоих сигналов телеметрия главнее CV; расхождение → понизить уверенность и подсветить на ревью.
3. **EDL по шаблонам**: шаблон — декларативные данные (слоты: «интервью 15–25 с», «выход: −3 с до отделения +10 после, обязателен», «падение 30–60 с, приоритет outside, вставки handcam с лучшими эмоциями»…). Движок заполняет слоты лучшими отрезками по CV-оценкам, укладывает под музыку, титры (имя, дата, ДЗ). На прыжок генерятся все настроенные варианты (полный/эмоции/хайлайты). В MVP шаблоны встроенные; редактор — бэклог.
4. **Прокси-рендер 720p** для ревью; правки оператора (границы, замена отрезков, трек, кроп-окно 9:16) меняют EDL.
5. **Финальный рендер** (ffmpeg, полное качество): склейки, переходы, музыка с даккингом под речь, титры, лого ДЗ → хранилище → статус «опубликован».

### Доставка и оплата

- Публикация → клиентская страница по ссылке-токену (без регистрации), отправка SMS/email + QR на стойке.
- Оплатившие пакет: просмотр/скачивание всех вариантов. Остальные: превью (полный — ~20 с + затухание, короткие — целиком с вотермарком) + «купить».
- `PaymentProvider`: `create_payment(order, amount, return_url)` → ссылка; вебхук → общий формат; `refund`. Адаптеры: **ЮKassa** (РФ), **Stripe** (США/мир). Валюта и провайдер — настройки ДЗ. Возвраты вручную в MVP.

### Обработка ошибок

Принцип: пайплайн никогда не теряет материал молча. Докачка + контрольные суммы при загрузке; ретраи шагов (3× с бэкоффом); упавший шаг → статус `needs_attention` с причиной в админке; нет телеметрии → CV+аудио; нет и этого → грубые эвристики + пометка «низкая уверенность»; ошибка рендера одного варианта не блокирует остальные.

## План реализации (этапы)

### Этап 0 — скелет проекта
Монорепо в `/Users/komo4ekk/happy_tandemista`: `backend/` (FastAPI + Celery), `web/` (Next.js), `uploader/` (Tauri), `docs/`. Docker Compose для локальной разработки (Postgres, Redis, MinIO как S3). CI-заготовка, git init, первый коммит.

### Этап 1 — MVP-ядро: автомонтаж (главная ценность и главный риск)
Ручная загрузка файлов прыжка через веб (`manual_web`) → пайплайн анализа (GPMF-парсер, аудио-профиль, CV-разметка, таймлайн) → EDL по трём встроенным шаблонам → прокси → экран ревью (плеер, таймлайн фаз, правка границ) → финальный рендер → страница клиента со всеми вариантами (без оплаты).
Мини-манифест: взлёты, клиенты, прыжки, устройства — руками в админке.
Критерий: реальный прыжковый день, оператор получает приличные ролики трёх форматов с ревью < 5 мин на прыжок.

### Этап 2 — сбор и метчинг
Аплоадер (Tauri, Win+macOS): детект карт, fingerprints устройств, копирование в StorageBackend (s3 + yandex_disk + network_drive), регистрация, докачка, автообновление. Автометчинг с окнами времени и подтверждением, очередь «неразобранное», калибровка clock_offset. Wi-Fi-выгрузка как отслеживаемая папка.

### Этап 3 — доставка и оплата
SMS/email-отправка ссылок, QR. Превью с вотермарком, Order, PaymentProvider + адаптеры ЮKassa и Stripe, открытие доступа по вебхуку.

### Этап 4 — качество и бэклог к SaaS
Гибрид телеметрия+CV тюнинг на реальных данных пилота, метрики точности фаз. Кабинет ДЗ (кастомизация, допродажи), редактор шаблонов, интеграции манифест-систем, PayPal — по приоритетам после пилота.

## Тестирование

- Юнит: детектор фаз на фикстурах реальных GPMF-дампов; метчинг по времени; генерация EDL из шаблонов.
- Интеграционные: пайплайн на коротких тестовых видео через реальный ffmpeg (в CI).
- Golden-тесты: эталонные наборы исходников → сравнение EDL (не пикселей).
- CV: вручную размеченный набор кадров → метрики точности фаз/эмоций, алерт при деградации.
- E2E — пилотный прыжковый день на дропзоне (цель этапа 1).

## Верификация MVP

1. `docker compose up` поднимает бэкенд+воркеры+веб локально.
2. Загрузить тестовый набор (handcam GoPro с GPMF + интервью + приземление) → система строит таймлайн с фазами, собирает 3 черновика.
3. В админке поправить границу одного клипа → перерендер прокси.
4. «Опубликовать» → финальные рендеры в хранилище, клиентская страница открывается по токен-ссылке, все варианты играют.
5. Юнит- и интеграционные тесты зелёные.
